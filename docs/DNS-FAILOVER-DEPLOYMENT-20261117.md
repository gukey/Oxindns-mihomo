# 国内 DNS 传输错误兜底：部署与测试

日期：2026-11-17，北京时间。用户明确要求“落地并测试”后，将此前验证的错误回退方案合并到手机实际配置。仅修改 OxiDNS 配置，通过原生 API 热重载；不修改核心、Mihomo 配置、节点、规则文件或防火墙。

## 最终改动

新增一个原生 `fallback` 插件，将 `main` 中匹配 `$china_domains` 的单个调用从 `$china_sequence` 改为 `$china_transport_fallback`：

```text
普通国内查询
  → fallback primary：原 china_sequence，内部保留原国内缓存与两路 DoH
  → primary 失败或没有回答：secondary 执行原 remote_sequence
```

[脱敏合并片段](examples/oxidns-transport-fallback.fragment.yaml)不包含节点、凭据、用户规则或实际设备配置，不能整份覆盖生产 YAML。

- 正常解析、NXDOMAIN、负缓存和 Lazy 策略均保持原定义。
- 国内缓存只包裹 primary 内部的国内解析，不包裹备用。备用回答在子请求中产生，不回写国内缓存。
- 手动直连的 `direct → china_sequence`、NCSI 专用序列保留原调用；失败时不会因本次变更强制转到代理。
- 普通国内 AAAA 成功仍返回真实 IPv6；国内失败后复用远端序列原有的 AAAA 空成功策略。
- 其余主序列步骤、手动规则、Google 下载 CDN 条件规则和 Mihomo 参数保留。

离线生成器检查：除 main 的该步骤及新增插件外，所有存活插件逐项结构相同；还原这两处后配置结构与部署前完全相同。

## 超时选择

国内上游仍为原来的每路 5 秒，Mihomo DNS 仍为原来的 8 秒。fallback 的 `threshold=6000ms`、`always_standby=false`：正常快速查询不启动备用，primary 提前报错或无回答时立即启动备用；primary 仍在执行且达到阈值时，也允许启动备用。

这是补错误回退，不是承诺切网后立即成功。若国内超时后备用也耗尽超时，可能需要约 13 秒及调度开销；短等待预算的客户端仍可能先行超时重试。不能把本次测试的备用快速成功当作所有网络上的恢复上限。以后调整任一超时或竞速阈值，需单独验证。

## 隔离验证

候选基于刚读取的手机在线完整配置，复制规则到专用临时目录，重定向记录器和缓存写入；使用实际手机二进制的独立副本。58 个插件完成初始化，保留四个 IPv4/IPv6 DNS server 定义；仅监听回环测试端口。下载器禁止缺失时下载，cron 保留定义但调整为测试窗口不会触发的间隔，未执行生产更新脚本。

两路国内与备用替换为本机可控 TCP DNS 应答器；测试域名与手动/NCSI 样例仅添加在隔离副本。先用 500ms 故障时限验证语义，再在隔离实例热重载为国内 5 秒进行补测。

最终 **21 项 TCP 查询断言通过**：

| 范围 | 验证结果 |
|---|---|
| 国内正常、单路慢、故障解除 | 取得国内真实地址 |
| SERVFAIL、REFUSED、连接关闭、双路超时 | 取得备用测试回答 |
| 国内和备用同时超时 | 正确返回 SERVFAIL，不伪装成功 |
| NXDOMAIN | 保留负响应，不请求备用 |
| 国内 AAAA | 正常时真实 IPv6；失败后按原远端策略空成功 |
| 手动直连 / NCSI | 超时仍失败，不请求备用 |
| 原远端 AAAA | 空成功行为保留 |
| 缓存隔离 | 备用故意返回 TTL 120 秒的测试 Fake-IP；恢复后相同名称立即取得国内真实地址，未命中该备用缓存 |
| 新鲜缓存 / Lazy | 上游失败时仍复用原有缓存行为；未因加兜底而取消 stale hit |
| 国内 5 秒超时 | 备用约 5.12 秒返回；恢复后回归国内回答 |

这些是受控解析行为验证，不是网络性能对照，也不是实际切换 Wi-Fi/移动数据。未在生产制造 DoH 故障。
