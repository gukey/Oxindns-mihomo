# OxiDNS 分流评估与 Google Play CDN 修复

日期：2026-11-16。本文记录一套 Android OxiDNS + Mihomo 自定义部署的排查结果，不是 NetPanel APP 自动执行的操作，也不是发布版 Root 模块的默认配置。未收录设备配置、节点、订阅、凭据或原始查询日志。

## 结论与适用范围

保留 OxiDNS 1.7.1 内核；没有测出新分流配置整体优于旧配置。DNS 解析成功不能作为下载链路可用的验收结果。此次 Google Play 问题实际涉及下载 CDN 的出站选择，应同时核对 DNS 应答、Mihomo 命中规则和实际 TLS/HTTP 请求。

本次在已授权设备上完成两项修复：

1. 将下载域名一律直连的临时规则，改成指定下载域名且真实目的地址属于 CN 时直连；境外目标继续匹配既有代理规则。
2. 停用依据 Fake-IP 判断国内外归属的自动学习，并取消历史学习名单对主分流的影响。保留原文件和插件标签，便于追溯、兼容和回退；静态规则、手动名单及现有国内缓存继续生效。

没有更换核心、修改节点或代理组选择、修改防火墙，也没有将这套自定义配置写入 APP 或通用 Root 模块。

## 升级前后究竟改变了什么

升级记录显示，此次并非只把 1.6.1 二进制换成 1.7.1，还把原有 MetaCubeX 分类顺序迁移为作者模板的国内、GFW、学习和兜底分支。随后又关闭了广告过滤、删除重复海外缓存，并调整了国内 DoH 转发和手机后台探测。

升级前备份中的实际查询记录提供了以下证据：

| 项目 | 旧配置及历史记录 | 新配置故障现场 |
|---|---|---|
| `services.googleapis.cn` | 命中 Google 分类，交给 Mihomo，返回 Fake-IP | 命中国内序列，返回境内真实 IP |
| `*.xn--ngstr-lra8j.com` | 已包含在 Google 域名集合，返回 Fake-IP | 仍返回 Fake-IP，并被 Mihomo 的 Google 规则接管 |
| 下载目标 | 历史记录包含另一组 CDN 主机名 | 本次失败的 CDN 真实地址属于 CN，走当前代理超时，直连可响应 |

因此，不能说“新版才开始代理下载域名”。可以确认的是部分 Google 接口出口发生变化、此次下载目标不同、原有代理路径无法访问这批下载目标。

接口出口变化可能影响 CDN 调度，但没有升级前完整 HTTP 重定向记录，尚不足以证明这条完整因果链。不能将时间上的先后关系直接归结为 OxiDNS 新内核缺陷，也不能把当前解析旧主机名获得的地址当成当年的真实目的地址。

## 新旧分流的随机配对测试

在同一台手机、同一 1.7.1 内核上运行两份仅绑定回环地址的临时实例：旧分流与当前分流。旧分类文件取自升级前归档；手动动态名单沿用当前文件。临时实例关闭定时任务，不使用生产缓存 dump，历史库和学习写入使用独立路径，不重启生产服务。

每组 5 个域名，排除预热轮后随机交替查询 12 轮，每组每配置 60 次，共 480 次计入统计。包括国内 A、海外 A、Apple HTTPS 和 Google/CDN A。手机测量经同一 ADB TCP 路径，包含传输开销；两份配置共享本机 Mihomo 和外部上游缓存，不是完全隔离的冷缓存实验。

| 类别 | 旧配置 P50 / P95 | 新配置 P50 / P95 |
|---|---:|---:|
| 国内 A | 17.004 / 53.738 ms | 17.818 / 76.095 ms |
| 海外 A | 18.193 / 52.216 ms | 16.676 / 53.965 ms |
| Apple HTTPS | 70.830 / 155.577 ms | 23.093 / 118.220 ms |
| Google/CDN A | 17.583 / 36.201 ms | 16.663 / 43.469 ms |

480 次计入统计的查询无传输错误、无非零 RCODE。四组配对差值的中位数 bootstrap 95% 区间均跨越 0；不能仅凭 Apple HTTPS 的整体 P50 差异宣传稳定提速。先前归档的 720 次配对测试比较的是迁移后的优化前后配置，与本次旧分流对照不是同一实验，其结论同样不支持整体提速。

没有测量升级前后的同条件下载带宽、长时间息屏可靠性或所有应用的行为；不提供相应提升百分比。减少重复缓存和后台探测是结构变化，不能代替实际性能证据。

## CDN 分流修复

适用于本次“境内下载 CDN 经代理超时、直连正常”的已验证场景。在既有 Mihomo 规则中、Google 分类之前加入：

```yaml
rules:
  - AND,((DOMAIN-SUFFIX,xn--ngstr-lra8j.com),(GEOIP,CN)),DIRECT
  - AND,((DOMAIN-SUFFIX,gvt1.com),(GEOIP,CN)),DIRECT
  # 后续保留自己的既有规则及策略组。
```

这是需要合并进已有列表的片段，不是完整配置。删除此前针对 `xn--ngstr-lra8j.com` 的无条件 DIRECT 临时规则。不要为 GEOIP 条件添加 `no-resolve`：本次需要依据真实目的地址作判断。保留已有 GeoIP 数据和代理侧 DNS 配置，不硬编码运营商 CDN IP，不全局设置 Google 直连，不关闭证书验证。

Mihomo v1.19.33 的 AND 规则按条件顺序匹配；先限定域名，再检查目的地址。相关依据：[官方路由规则文档](https://wiki.metacubex.one/config/rules/)、[对应版本逻辑规则实现](https://github.com/MetaCubeX/mihomo/blob/v1.19.33/rules/logic/logic.go)、[官方 DNS 配置](https://wiki.metacubex.one/config/dns/)。GeoIP 分类、DNS 策略和出口质量依赖实际部署，本片段不是所有 Google 访问问题的通用解决方案。

## 修正 Fake-IP 自动学习

当前链路中，兜底 DNS 上游是启用了 Fake-IP 的 Mihomo。用 `198.18.0.0/16` 的合成地址与中国 GeoIP 集合比较，不能得出域名真实归属；“不是中国 IP”的结果只是合成地址特性。

本次在 OxiDNS 中完成以下语义调整，其他转发和手动规则不变：

- `final_sequence` 不再执行 `$learn_china`、`$learn_foreign`。
- `gfw_domains` 不再引用 `$learned_foreign`，保留静态 GFW 名单。
- `china_domains` 不再引用 `$learned_china`，保留国内静态名单、GeoSite CN 与原 `domain:cn`。

这不等于对未知域名直接放行。未知域名仍进入现有 Mihomo 兜底，再由代理侧规则决定出站。保留学习文件作为历史材料，不继续把合成地址的分类结果反馈为路由依据。

## 验证与回退

- 两份核心候选通过配置校验；OxiDNS 候选隔离启动后 30 项 A/AAAA/HTTPS 查询通过。
- 应用后 33 项生产 DNS 查询通过，包含国内、海外、Google/CDN、Apple HTTPS 及一个测试用未知主机名。
- 生产请求跟踪不再执行学习插件；查询前后两份学习文件内容哈希一致。
- 两个境内 CDN 实际命中 AND/DIRECT；一个境外同后缀 CDN 和一个境外 gvt1 CDN 继续命中既有 Google 代理规则。四个测试均通过证书验证并返回 HTTP 响应。根路径返回 404 只证明到达服务器，不代表实际应用文件下载成功。
- 手机默认路径与显式 HTTP 代理均完成 Google 下载入口重定向，获取同一份 384,394 字节仓库元数据文件，HTTP 200。
- OxiDNS 异步重载按完成状态及运行配置哈希确认，未把 HTTP 202 accepted 当成重载成功。文件使用 LF 换行，以避免换行归一化产生哈希差异。
- 临时核心实例及本次 ADB 转发已清理。生产配置备份保留在设备上，原始日志、配置、逐对测量样本仅保存在本机忽略目录，不进入本仓库。

修改前逐份备份配置；回退时恢复相应备份并通过各自管理接口重载，核对实际运行规则和 OxiDNS 重载完成状态。不要恢复旧查询数据库、清空整个 Fake-IP 映射、删除应用数据或切换节点来代替分流诊断。

此前无条件直连修复已经由用户确认 Play 恢复下载；本轮细化修复后，用户再次更新应用并确认“可以更新”。因此，本次同时完成了分流规则、TLS/HTTP、真实文件下载与 Play 实际应用更新验收。该结果不代表已覆盖所有应用、后续 CDN 调度或所有网络环境。
