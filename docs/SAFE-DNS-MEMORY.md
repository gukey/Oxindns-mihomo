# DNS 自动学习的保守重设计

日期：2026-11-16。适用前提：保持 OxiDNS 1.7.1 与 Mihomo 核心不变，不新增常驻进程、数据库或自动节点切换。

## 决策

将“自动记住域名应该走哪条路线”拆成三个部分：

| 部分 | 本版行为 | 是否自动改变路由 |
|---|---|---|
| 观察 | 复用现有查询记录，排错时核对真实应答、规则和实际访问结果 | 否 |
| 短期应答记忆 | 在明确的公网解析分支内，使用有容量和 TTL 限制的原生缓存 | 否 |
| 路由修正 | 形成精确、可回退的显式规则；经过验证后人工确认 | 是，但不由学习插件自行提交 |

**当前实现的是经过验证的缓存设计，不是重新开启持久路由学习。** 手机生产配置仍保持此前修复后的状态，本次未更换现网缓存或开启学习名单。配置样例仅运行过回环隔离验证。

## 为什么不能直接恢复原学习插件

核对 1.7.1 对应源码后，`learn_domain` 支持学习时机、完整名称/后缀选择、异步写入和错误策略；`dynamic_domain_set` 支持文件、队列和批量刷新。但这两个插件没有逐条有效期、条目容量上限或 DNS TTL 绑定参数。

不能把不存在的 `ttl`、`max_entries` 等字段写入 YAML 后宣称已经具备自动过期能力，也不能把队列大小误认为已保存的规则数量上限。可核对：[学习插件配置](https://github.com/svenshi/oxidns/blob/v1.7.1/src/plugin/executor/learn_domain/config.rs)、[动态名单配置](https://github.com/svenshi/oxidns/blob/v1.7.1/src/plugin/provider/dynamic_domain_set/config.rs)。

真实 IP 也只代表一次 DNS 应答，不能证明整个域名长期归属。CDN 可能随出口、运营商、ECS 和时间改变；把域名永久加入国内或海外名单会再次引入失配。因此，本版不恢复 `$learn_china`、`$learn_foreign` 的生产调用，也不重新让旧学习名单影响主路由。

## 路由职责和优先级

保留当前已验证的架构：

1. 本地 hosts、内部域名、明确手动规则按原有逻辑处理。
2. 静态服务分类决定进入本地真实 DNS 或 Mihomo 分支，不被观察记录覆盖。
3. Google 下载 CDN 进入 Mihomo 时，按已验证的域名与真实目的地址 CN 条件选择直连；境外地址继续走既有代理规则。
4. 未知域名继续进入既有 Mihomo 兜底，不使用合成地址推断归属。

DNS 的短期应答缓存不增加新的路由优先级。不能把该缓存放在整个主分流最前面，否则可能让旧应答绕过后续手动规则。

## 短期应答记忆的具体参数

[可启动的回环样例](examples/oxidns-safe-memory.yaml)用于验证原生能力，不能整份替换生产配置。

| 项目 | 设计 |
|---|---|
| 范围 | 仅明确的公网真实 DNS 分支；Google/Play 下载流量继续由既有 Mihomo 分支处理 |
| 缓存键 | 由内核区分规范化域名、查询类型及查询上下文；启用 ECS 入键 |
| 容量 | 原生 `size: 4096`，不创建永久域名名单 |
| 有效期 | 遵守 DNS 应答 TTL，本地正应答缓存上限 300 秒 |
| 过期行为 | 不设置 `lazy_cache_ttl`，到期重新查询，不提供过期应答 |
| 低 TTL | 不人为延长；TTL 为 0 的应答不缓存 |
| 负响应 | 本版不缓存 NXDOMAIN/NODATA，避免把短暂异常变成持久路由结论 |
| 持久化 | 不设置 `dump_file`，不恢复跨重启短期应答 |
| 地址保护 | 在公网样例分支拒绝列出的 Fake-IP、私网、回环及保留范围，避免写入缓存 |

缓存上限控制的是 OxiDNS 本地保存时间。首次上游应答的 TTL 不会仅因 `max_positive_ttl` 自动改写为 300 秒；客户端和其他 DNS 层仍可能按原 TTL 缓存。不能把本地上限宣传成所有客户端的最大记忆时间。依据：[对应版本缓存实现](https://github.com/svenshi/oxidns/blob/v1.7.1/src/plugin/executor/cache/mod.rs)。

样例的地址保护会将匹配应答改为 SERVFAIL，并非仅做“跳过缓存”。因此必须限制在公网分支，局域网和 hosts 前置单独处理，不能用于需要返回私网地址的分离 DNS。示例列表是一组明确的排除范围，不是自动更新的全球地址分类器；它也不替代连接时的安全与可达性判断。参考：[IANA IPv4 特殊用途地址](https://www.iana.org/assignments/iana-ipv4-special-registry)、[IANA IPv6 特殊用途地址](https://www.iana.org/assignments/iana-ipv6-special-registry)。

本版没有新增网络切换监听。不能宣称切换 Wi-Fi/蜂窝后缓存会自动清空，也不能通过无限延长 TTL 换取缓存命中率。

## 观察记录怎样变成显式规则

观察复用现有查询历史的保留策略，不创建另一个学习日志服务。排查时只读取有关域名的记录，不导出整份历史。

一个候选必须有真实应答与访问证据：核对完整域名、A/AAAA/HTTPS 类型、CNAME、原 TTL、DNS 上游、实际命中规则、访问出口和 TLS/HTTP 结果。Fake-IP、空回答、NXDOMAIN、SERVFAIL、单次超时或一次 GEOIP 命中都不构成自动改路由的依据。

即便有多次样本，也不把 CDN 子域名提升成整个父域名的长期规则。优先使用能表达实际意图的条件，例如“特定下载域名且真实地址属于 CN 时直连”。规则仍需备份、校验、重载和真实业务验收；不自动切换代理节点。

## 隔离验证结果

在手机 1.7.1 核心上使用回环测试实例，以及只存在于测试端口的受控 DNS 应答源，完成 12 项行为检查：

- TTL 为 2 秒时，过期前两次查询仅访问上游一次；改变应答并等待到期后，重新请求上游并获得新地址。
- Fake-IP、私网及另一段基准测试地址均返回 SERVFAIL、不缓存，每次重新访问测试上游。
- 零 TTL 和负响应均不缓存。
- 上游 TTL 为 600 秒时，后续本地缓存回答的剩余 TTL 为 299 秒，符合本地 300 秒上限。
- IPv6 ULA、回环、模拟 Fake-IP 均被拒绝；正常公网 IPv6 可以缓存。
- 同一应答同时包含公网地址和 Fake-IP 时被拒绝，不因存在一个公网地址而放行。

这组受控测试用于验证缓存逻辑，不是线上 DNS 指标或 Play 下载结果，不用于首页展示。它未验证容量压力、长期息屏、所有 IPv6 特殊范围、网络切换或所有 CDN 行为。

测试前后两份生产配置哈希一致；测试核心、ADB forward/reverse 均已清理。设备节点、凭据、实际配置和原始运行日志不进入仓库。

## 后续边界

如果未来核心原生提供逐条过期、容量限制、网络/出口上下文和候选观察模式，再考虑真正的短期路由建议。届时仍应从完整域名开始，过期时间不超过真实应答 TTL，排除 Fake-IP 与混合应答，冲突时交还静态规则，并先观察后应用。

这些能力当前没有实现，也不是现有 YAML 可以开启的隐藏选项。本次不修改核心来补齐它们，不增加定时清空永久名单的辅助守护进程。
